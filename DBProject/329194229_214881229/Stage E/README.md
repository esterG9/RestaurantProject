## 🔌 הוראות כניסה והפעלה

### דרישות קדם:
1. **Python 3** מותקן במערכת.
2. בסיס הנתונים **PostgreSQL** פעיל בתוך Docker (על פי קובץ ה-`docker-compose.yml` של הפרויקט).
3. חבילת הנהג של PostgreSQL עבור פייתון מותקנת. ניתן להתקין אותה באמצעות הפקודה:
   ```bash
   py -m pip install psycopg2-binary flask flask-cors python-dotenv
   ```

### הוראות הרצה:
1. ודא כי בסיס הנתונים של Docker רץ ותקין.
2. **אפשרות א' - הרצה מהירה (הכי פשוט):** פתחי את התיקייה הזו במחשב ולחצי דאבל-קליק על הקובץ **`run.bat`** (הוא יבצע את ההתקנות וההרצה אוטומטית).
3. **אפשרות ב' - הרצה משורת הפקודה (CMD / PowerShell):**
   * פתחי את שורת הפקודה והקלידי את פקודת הניווט (כולל המירכאות):
     ```bash
     cd "C:\RestaurantProject\DBProject\329194229_214881229\Stage E"
     ```
   * הריצי את השרת באמצעות הפקודה:
     ```bash
     py app.py
     ```
4. שרת האינטרנט המקומי יתחיל לפעול בכתובת `http://localhost:5000` והדפדפן שלך **ייפתח אוטומטית**. במידה ולא, הקלידי ידנית בדפדפן: `http://localhost:5000`.

## 🛠️ הסבר על דרך העבודה והכלים

הממשק נבנה כאתר אינטרנט עשיר בעיצוב מודרני מטיפוס **Single Page Application (SPA)**, המאפשר עבודה מהירה ללא טעינת דפים מחדש.

### טכנולוגיות וכלי פיתוח:
1. **שרת Backend (Python + Flask)**:
   - נבחר בגלל קלות השילוב עם בסיס הנתונים ותמיכה רחבה ב-JSON.
   - מתחבר ל-PostgreSQL (`IntegratedDB`) באמצעות הספרייה **`psycopg2`** ושאילתות פרמטריות מאובטחות (מונע SQL Injection).
   - חושף נקודות קצה (REST API) לביצוע פעולות CRUD לכל 16 הטבלאות, הרצת 8 שאילתות מורכבות משלב ב', והפעלת פונקציות ופרוצדורות משלב ד'.
2. **ממשק Frontend (HTML5, Vanilla CSS3, Javascript ES6)**:
   - מעוצב בשיטת **Glassmorphism** עם צבעים דינמיים מבוססי HSL, פונטים מודרניים מ-Google Fonts (`Assistant` ו-`Outfit`), ואפקטים של תאורה וצלליות ניאון ליצירת מראה יוקרתי (Premium).
   - נעשה שימוש ב-Vanilla CSS לשליטה מרבית בעיצוב ללא תלות בספריות עיצוב חיצוניות כגון Tailwind.
   - משתמש ב-Vanilla JS לביצוע קריאות `fetch` אסינכרוניות לשרת ועדכון ה-DOM בצורה דינמית.

### מנגנונים מיוחדים בממשק:
* **הסתרת מפתחות זרים (Foreign Keys Display Mappings)**: בכל הטבלאות, המערכת מבצעת שאילתות `LEFT JOIN` מאחורי הקלעים כדי להציג שמות משמעותיים במקום מזהי מספרים (לדוגמה: מראה את שם המדינה "Albania" במקום מזהה מדינה `1`, או את שם המסעדה "Jayo" במקום מזהה מסעדה `12`).
* **טעינת נתונים אוטומטית בזמן עדכון (Autofill on Key Input)**: בדף עריכת רשומה, כאשר המשתמש מזין את המפתח הראשי (Primary Key) ולוחץ על כפתור "טען לפי מפתח", המערכת פונה לשרת, שולפת את פרטי הרשומה הקיים ומאכלסת אוטומטית את כל שאר שדות הטופס. משם המשתמש יכול לשנות וללחוץ על שמירה כדי לעדכן.
* **הצגת השפעת פרוצדורות (DB Effects Visualizer)**: כאשר מריצים פרוצדורה המשנה נתונים בבסיס הנתונים (כגון עדכון מחירי הלינה של מארח מסוים ב-`5%`), המערכת מציגה טבלה השוואתית המציגה את מחירי הדירות **לפני** העדכון ו**לאחר** העדכון, כך שהמשתמש רואה מיד את השפעת הרצת הפרוצדורה.

## 📂 מבנה קבצי הממשק

* **`app.py`**: שרת ה-Flask הראשי המנהל את הלוגיקה מול בסיס הנתונים ומגיש את ה-API.
* **`run.bat`**: קובץ הרצה מהיר עבור סביבת Windows.
* **`static/`**: תיקיית קבצי ה-Frontend הסטטיים:
  - **`index.html`**: שלד הדף ומבנה לוח הבקרה, טפסים ומודאלים.
  - **`style.css`**: קובץ העיצוב המלא (צבעי HSL, עיצוב Glassmorphism, כפתורים, תצוגת קונסול פלט, תגובתיות למובייל).
  - **`app.js`**: קוד ה-JavaScript המנהל את הלוגיקה של הממשק, טעינת אפשרויות למפתחות זרים (Dropdown selectors), קריאות ה-API, וטיפול במודאלים.
* **`images/`**: תמונות מסך של האפליקציה בפעולה.
